# Power BI build guide

Every file this guide uses is in this folder and is regenerated by the pipeline
(`make export-powerbi`, also part of `make all`). **No `.pbix` file exists yet**; the website
lists the dashboard as "not yet available" until you publish one and add its link to
`config/site.yaml` (`powerbi_url`).

Terminology: say **payment-difficulty rate** on every visual. The CSVs already use the column
name `payment_difficulty_rate`, so no renaming is needed. Columns named `bads…` count
applications with payment difficulties; label them "with payment difficulties" on visuals.

No number in this guide needs to be typed into Power BI: the recommended cut-off, the slider
range and the baselines are all read from the files below.

## Files

| File | Rows | Columns |
|---|---|---|
| `metrics.csv` | one per split: `train`, `validation`, `test`, `full_population` | `split`, `applications`, `payment_difficulty_rate`, `auc`, `gini`, `ks` (AUC, Gini and KS are blank on the full-population row) |
| `recommendation.csv` | one | `cutoff`, `rule`, `val_approval_rate`, `val_payment_difficulty_rate`, `test_approval_rate`, `test_payment_difficulty_rate`, `baseline_payment_difficulty_rate` (approve-everyone rate on validation) |
| `segments.csv` | one per segment | `dimension`, `segment`, `n`, `bads`, `payment_difficulty_rate`, `ci_low`, `ci_high`, `lift`, `portfolio_share`, `risk_rank`, `segment_order`, `dimension_complete` |
| `iv_summary.csv` | one per candidate feature | `feature`, `dtype`, `iv`, `n_bins`, `leak_flag`, `decision`, `reason` |
| `scorecard.csv` | one per bin of each scorecard feature | `feature`, `bin_index`, `bin`, `count`, `payment_difficulty_rate`, `woe`, `coefficient`, `points_exact`, `points` |
| `score_distribution.csv` | one per score band and split | `split`, `band_order`, `score_band`, `band_low`, `band_high`, `count`, `bads`, `payment_difficulty_rate`, `share` |
| `cutoff_table.csv` | one per cut-off (validation split) | `cutoff`, `approved`, `approval_rate`, `goods_approved`, `bads_approved`, `payment_difficulty_rate`, `bads_avoided`, `goods_rejected`, `profit` |
| `sensitivity.csv` | one per assumption scenario | `avg_loan_level`, `margin_level`, `loss_given_bad_level`, `avg_loan`, `margin`, `loss_given_bad`, `n_changed`, `recommended_cutoff`, `approval_rate`, `payment_difficulty_rate`, `profit`, `shift_vs_base` |
| `coefficients.csv` | intercept + one per scorecard feature | `feature`, `coefficient`, `expected_sign`, `sign_ok`, `univariate_coefficient`, `vif`, `max_corr_feature`, `max_corr` |
| `theme.json` | — | report theme (colours) |

## 0. Load and shape the data

1. **Home → Get data → Text/CSV**: load `metrics.csv`, `recommendation.csv`, `segments.csv`,
   `iv_summary.csv`, `scorecard.csv`, `score_distribution.csv`, `cutoff_table.csv` and
   `sensitivity.csv`. Keep the default table names (the file name without `.csv`).
   `coefficients.csv` is optional (a table of model coefficients for an appendix page).
2. **View → Themes → Browse for themes** → `theme.json`.
3. In **Power Query**, check the types: every `*_rate`, `ci_low`, `ci_high`, `lift`,
   `portfolio_share`, `share`, `iv`, `woe`, `auc`, `gini`, `ks`, `profit` column → *Decimal
   number*; counts (`applications`, `n`, `bads`, `count`, `approved`, `cutoff`, `points`…) →
   *Whole number*. In `metrics`, blank `auc`/`gini`/`ks` stay null.
4. Format every `*_rate`, `share` and `portfolio_share` column as **Percentage** (Column tools).
5. No relationships are needed.
6. Create a measures table: **Home → Enter data**, one empty column, name the table `_Measures`.

### Shared measures (on `_Measures`)

```DAX
Applications =
    LOOKUPVALUE ( metrics[applications], metrics[split], "full_population" )

Baseline payment-difficulty rate =
    LOOKUPVALUE ( metrics[payment_difficulty_rate], metrics[split], "full_population" )

Test Gini = LOOKUPVALUE ( metrics[gini], metrics[split], "test" )

Recommended cut-off = MAX ( recommendation[cutoff] )

Validation baseline rate = MAX ( recommendation[baseline_payment_difficulty_rate] )
```

## Page 1 — Portfolio risk

```DAX
Segment payment-difficulty rate = DIVIDE ( SUM ( segments[bads] ), SUM ( segments[n] ) )

Segment lift = DIVIDE ( [Segment payment-difficulty rate], [Baseline payment-difficulty rate] )
```

1. **KPI cards** (Card): `[Applications]`, `[Baseline payment-difficulty rate]`.
2. **Dimension slicer**: field `segments[dimension]`, single select, style *Dropdown*.
3. **Segment lift bar chart** (Clustered bar): Y-axis `segments[segment]` — set *Sort by
   column* of `segment` to `segments[segment_order]` — X-axis `[Segment lift]`. Analytics →
   *Constant line* at 1, labelled "Portfolio baseline". Bar colour: Format → Bars → *fx* →
   rules on `[Segment lift]`: greater than 1 → `#B4552D`, otherwise `#2E6B4F`.
4. **Portfolio share vs rate scatter**: X `segments[portfolio_share]`, Y
   `segments[payment_difficulty_rate]` (both *Don't summarize*), Legend `segments[dimension]`,
   Values `segments[segment]`, Size `segments[n]`. Analytics → Y-axis *Constant line* bound
   (*fx*) to `[Baseline payment-difficulty rate]`.
5. Tooltips on both visuals: `segments[n]`, `segments[ci_low]`, `segments[ci_high]`.

## Page 2 — Scorecard

1. **KPI cards**: `[Test Gini]`; a Table visual on `metrics` with `split`, `applications`,
   `auc`, `gini`, `ks` (filter out `full_population` if you prefer).
2. **IV by feature** (Clustered bar): Y `iv_summary[feature]`, X `iv_summary[iv]`; visual
   filter `iv_summary[decision]` is `selected`; sort by `iv` descending. Analytics → three
   constant lines at 0.02 (weak), 0.1 (medium) and 0.3 (strong) — conventional IV strength
   bands, not results.
3. **Points table** (Matrix): Rows `scorecard[feature]`, then `scorecard[bin]` (*Sort by
   column* `scorecard[bin_index]`); Values `scorecard[woe]`, `scorecard[points]`,
   `scorecard[count]` (*Don't summarize* / Sum). Format → Row subtotals off.
4. **Score-band payment-difficulty rate** (Clustered column): X `score_distribution[score_band]`
   (*Sort by column* `score_distribution[band_order]`), Y
   `score_distribution[payment_difficulty_rate]` (Average), Legend `score_distribution[split]`.

## Page 3 — Cut-off strategy

1. **Cut-off slider table** — Modeling → *New table*:

   ```DAX
   Cutoff = SELECTCOLUMNS ( cutoff_table, "Cutoff", cutoff_table[cutoff] )
   ```

   Add a Slicer on `Cutoff[Cutoff]`, style *Single value* (a slider). Its range and steps come
   from `cutoff_table`, so nothing is typed.

2. Measures (on `_Measures`):

   ```DAX
   Cutoff Value = SELECTEDVALUE ( Cutoff[Cutoff], [Recommended cut-off] )

   Approval rate at cut-off =
       LOOKUPVALUE ( cutoff_table[approval_rate], cutoff_table[cutoff], [Cutoff Value] )

   Payment-difficulty rate at cut-off =
       LOOKUPVALUE ( cutoff_table[payment_difficulty_rate], cutoff_table[cutoff], [Cutoff Value] )

   Applicants approved at cut-off =
       LOOKUPVALUE ( cutoff_table[approved], cutoff_table[cutoff], [Cutoff Value] )

   Illustrative profit at cut-off =
       LOOKUPVALUE ( cutoff_table[profit], cutoff_table[cutoff], [Cutoff Value] )

   Rate change vs baseline (pp) =
       ( [Payment-difficulty rate at cut-off] - [Validation baseline rate] ) * 100

   Test approval rate at recommended = MAX ( recommendation[test_approval_rate] )

   Test payment-difficulty rate at recommended = MAX ( recommendation[test_payment_difficulty_rate] )
   ```

   With nothing selected, `[Cutoff Value]` falls back to the recommended cut-off.

3. **KPI cards**: `[Approval rate at cut-off]`, `[Payment-difficulty rate at cut-off]` (with
   `[Rate change vs baseline (pp)]` as a second card or subtitle), `[Applicants approved at
   cut-off]`, `[Illustrative profit at cut-off]` titled "Expected profit — illustrative,
   assumption-based".
4. **Trade-off line chart**: X `cutoff_table[cutoff]` (Continuous), Y
   `cutoff_table[approval_rate]`, secondary Y `cutoff_table[payment_difficulty_rate]`.
   Analytics → X-axis constant line bound (*fx*) to `[Cutoff Value]` labelled "Selected",
   and a second bound to `[Recommended cut-off]` labelled "Recommended".
5. **Profit line chart**: X `cutoff_table[cutoff]`, Y `cutoff_table[profit]`; the same two
   constant lines.
6. **Held-out test check** (two cards): `[Test approval rate at recommended]`,
   `[Test payment-difficulty rate at recommended]`; a Card on `recommendation[rule]`.
7. **Sensitivity table** (Table): `sensitivity[avg_loan_level]`, `sensitivity[margin_level]`,
   `sensitivity[loss_given_bad_level]`, `sensitivity[recommended_cutoff]`,
   `sensitivity[shift_vs_base]`.
8. **Assumptions note** (Text box, background `#F5EBD7`, text `#8A5A00`): "Profit uses
   illustrative assumptions (average loan, margin, loss given payment difficulty) from
   config/assumptions.yaml. They are not Home Credit figures and exclude funding cost,
   operating cost, fees, recovery timing and loan term. The cut-off table is computed on the
   validation split."

## Publishing

Publish to the Power BI service, copy the public link, put it in `config/site.yaml`
(`powerbi_url`) and re-run `make export-web`. Until then the site says the dashboard is not
yet available.
